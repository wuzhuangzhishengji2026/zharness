# 二次扫描：黑盒可利用性评估

## 一、评估目标

从黑盒渗透测试视角，评估代码审计发现的高危/超危漏洞的"可利用性"，帮助研发团队优先修复那些最容易被外部攻击者发现和利用的漏洞。

## 二、评估模型（5维度评分）

### 维度1：入口点暴露度（30%权重）

**评估标准（Web场景）**：
- 漏洞是否位于公开API端点（HTTP入口）？
- 是否在Swagger/OpenAPI文档中公开？
- 是否有调试端点、管理端点暴露？
- 是否有可预测的API路径模式（容易被fuzz发现）？

**评估标准（非Web场景/C++特有）**：
- 漏洞是否在IPC通信入口（共享内存、消息队列、管道、Socket）？
- 漏洞是否在文件解析入口（读取外部文件、解析配置文件）？
- 漏洞是否在网络协议处理入口（监听端口、处理自定义协议）？
- 漏洞是否在命令行参数处理入口（解析命令行参数）？
- 漏洞是否在环境变量处理入口（读取环境变量）？

**评分规则**：
- 公开入口（HTTP端点、IPC端点、文件解析入口）：25-30分
- 受限入口（需要认证的API、权限控制的IPC）：15-24分
- 内部入口（需要特定条件触发）：5-14分
- 无直接外部入口（纯内部逻辑）：0-4分

### 维度2：认证要求（25%权重）

**评估标准**：
- 是否需要认证？
- 是否在公开路径中？
- 是否有权限检查函数调用？
- 是否存在认证绕过可能性？

**评分规则**：
- 无需认证（公开路径）：20-25分
- 需要认证但可能被绕过：15-19分
- 需要认证且防护良好：5-14分
- 需要高权限认证（管理员）：0-4分

### 维度3：攻击复杂度（20%权重）

**评分规则**：
- 一步到位、无需特殊条件：16-20分
- 两步利用、条件简单：12-15分
- 三步及以上、条件较复杂：6-11分
- 需要链利用或社会工程：0-5分

### 维度4：过滤校验有效性（15%权重）

**评分规则**：
- 无任何过滤校验：12-15分
- 有基本过滤但可绕过（如黑名单不完整）：8-11分
- 有部分过滤（类型校验、长度校验）：4-7分
- 有完善过滤（白名单、安全API、多层校验）：0-3分

### 维度5：自动化可探测性（10%权重）

**评分规则**：
- 极易被自动化工具发现：8-10分
- 可能被自动化工具发现：5-7分
- 较难被自动化工具发现：2-4分
- 几乎不可能被自动化工具发现：0-1分

## 三、综合评分

**总分 = 入口点暴露度 + 认证要求 + 攻击复杂度 + 过滤校验有效性 + 自动化可探测性**

**优先级判断**：
- **≥80分**：优先修复（极易被黑盒渗透发现）
- **50-79分**：建议修复（可能被发现）
- **<50分**：后续修复（较难被发现）

## 四、各类漏洞的攻击路径评估

### SQL注入
- 检查是否在公开API端点
- 检查参数是否来自用户可控输入
- 检查是否有WAF防护
- 检查错误信息是否泄露SQL结构

### 命令注入
- 检查是否在公开API端点
- 检查参数是否直接传递给系统命令
- 检查是否有输入过滤或命令白名单
- 检查操作系统权限级别

### 路径遍历与文件操作
- 检查是否在公开API端点
- 检查路径参数是否有目录遍历限制
- 检查文件扩展名过滤是否完善
- 检查文件上传是否有类型校验

### 缓冲区溢出（C++特有）
- 检查是否在外部输入入口（网络数据、文件解析、IPC通信）
- 检查输入长度是否可控
- 检查是否有边界检查（strlen、size检查）
- 检查是否使用安全API（strncpy、snprintf、std::string）
- 检查是否有内存保护机制（ASLR、DEP、Canary、SafeSEH）

### 释放后使用（UAF，C++特有）
- 检查是否在外部输入入口
- 检查指针生命周期管理是否完善
- 检查是否使用智能指针（std::unique_ptr、std::shared_ptr）
- 检查是否有内存安全工具检测（ASan、Tsan）

### 整数溢出（C++特有）
- 检查是否在外部输入入口
- 检查是否有整数范围检查
- 检查是否使用安全整数类型（std::int32_t等）
- 检查是否有编译器保护（-fsanitize=integer）
