# 二次扫描：黑盒可利用性评估（Java）

## 一、评估目标

从黑盒渗透测试视角，评估代码审计发现的高危/超危漏洞的"可利用性"，帮助研发团队优先修复那些最容易被外部攻击者发现和利用的漏洞。

## 二、评估模型（5维度评分）

### 维度1：入口点暴露度（30%权重）

**评估标准**：
- 漏洞是否位于公开API端点（HTTP入口）？
- 是否在Swagger/OpenAPI文档中公开？
- 是否有调试端点、管理端点暴露？
- 是否有可预测的API路径模式（容易被fuzz发现）？

**评分规则**：
- 公开API端点、在文档中公开：25-30分
- 公开API端点、不在文档中：20-24分
- 认证后API端点：10-19分
- 内部方法（无直接HTTP入口）：0-9分

### 维度2：认证要求（25%权重）

**评估标准**：
- 是否需要认证？
- 是否在permitAll/anonymous路径中？
- 是否有@PreAuthorize、@Anonymous等认证注解？
- 是否存在认证绕过可能性（JWT校验缺陷、路径遍历绕过等）？

**评分规则**：
- 无需认证（permitAll/anonymous）：20-25分
- 需要认证但可能被绕过：15-19分
- 需要认证且防护良好：5-14分
- 需要高权限认证（管理员）：0-4分

**认证框架判断规则（Java/Spring）**：
- `@Anonymous`：允许匿名访问，无需认证
- `@PermitAll`：允许所有用户访问，无需认证
- `@PreAuthorize("hasRole('ADMIN')")`：需要管理员角色
- `@PreAuthorize("hasAuthority('USER')")`：需要用户权限
- `@Secured("ROLE_ADMIN")`：需要管理员角色
- `.permitAll()`：无需认证的路径
- `.authenticated()`：需要认证的路径
- `.hasRole("ADMIN")`：需要管理员角色的路径

### 维度3：攻击复杂度（20%权重）

**评分规则**：
- 一步到位、无需特殊条件：16-20分
- 两步利用、条件简单：12-15分
- 三步及以上、条件较复杂：6-11分
- 需要链利用或社会工程：0-5分

### 维度4：过滤校验有效性（15%权重）

**评分规则**：
- 无任何过滤校验：12-15分
- 有基本过滤但可绕过（如黑名单不完整）：8-11分
- 有部分过滤（类型校验、长度校验）：4-7分
- 有完善过滤（白名单、安全API、多层校验）：0-3分

### 维度5：自动化可探测性（10%权重）

**评分规则**：
- 极易被自动化工具发现：8-10分
- 可能被自动化工具发现：5-7分
- 较难被自动化工具发现：2-4分
- 几乎不可能被自动化工具发现：0-1分

## 三、综合评分

**总分 = 入口点暴露度 + 认证要求 + 攻击复杂度 + 过滤校验有效性 + 自动化可探测性**

**优先级判断**：
- **≥80分**：优先修复（极易被黑盒渗透发现）
- **50-79分**：建议修复（可能被发现）
- **<50分**：后续修复（较难被发现）

## 四、各类漏洞的攻击路径评估

### SQL注入
- 检查是否在公开API端点
- 检查参数是否来自用户可控输入
- 检查是否有WAF防护
- 检查错误信息是否泄露SQL结构

### 命令注入
- 检查是否在公开API端点
- 检查参数是否直接传递给系统命令
- 检查是否有输入过滤或命令白名单
- 检查操作系统权限级别

### 路径遍历与文件操作
- 检查是否在公开API端点
- 检查路径参数是否有目录遍历限制
- 检查文件扩展名过滤是否完善
- 检查文件上传是否有类型校验

### 认证绕过
- 检查是否在permitAll路径中
- 检查认证逻辑是否有缺陷
- 检查JWT校验是否完善
- 检查是否有@Anonymous注解滥用

### 越权访问（IDOR）
- 检查对象ID是否可预测（顺序数字、UUID）
- 检查是否有权限校验逻辑
- 检查是否有批量赋值漏洞
- 检查是否有水平/垂直权限提升可能
